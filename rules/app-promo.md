# App / 网页产品宣传片

适用：用户说「用网页版 / App 录屏做个宣传片」「演示主要功能」「做个推广视频发给同事 / 客户」。
和 `references/scenes/promo.md`（纯 BGM 的游戏 / 活动宣传片）的区别：这里画面是**产品真实录屏**，有**中文解说 + 字幕**，节奏是**广告式**（钩子 → 反转 → 卖点快切 → 高潮 → 行动号召）。

流程借鉴 [video-shotcraft](https://github.com/Vincentwei1021/video-shotcraft) 的分阶段做法，按剪映草稿的能力和这次实战（`rules/pitfalls.md`）落地。

## 0. 先定模式（问用户，不要默认）

| 模式 | 什么时候用 | 你要停下来确认的点 |
|---|---|---|
| 自主 | 用户说「你看着办」「直接出」 | 无，做完给成片 + 决策说明 |
| 共创（默认推荐） | 正式对外、要发给客户 / 领导 | 产品要点、卖点清单与顺序、视觉方向、分镜表 |
| 套模板 | 用户已有满意的成片 / 草稿 | 只换录屏、文案、品牌色 |

用户明确说了的约束（时长、画幅、平台、配音、哪些话不能说）是硬约束。**宣传口径要和用户确认**：比如「所有功能免费」「最好用」这类说法，用户没同意就不要写进解说、大字和结尾卡（2026-11-10 实测：用户中途要求删掉「全部免费」）。

## 1. 产品理解（只读）

- 看代码 / 文档 / 线上页面，列出功能、主要页面、品牌色、字体、Logo。
- 列出**数据风险**：真实账号、孩子姓名、手机号、内部地址。录屏用测试账号；敏感内容先换成示例数据，或在录屏里避开。
- 产出一张「需求 → 决定」表：用户要求 → 怎么满足（例：「发给同事看」→ 竖屏 1080×1920，不考虑短视频平台安全区）。

## 2. 卖点到镜头映射

每个要展示的功能一行：

| 卖点 | 一句话（≤ 15 字，口播用） | 录屏动作 | 镜头时长 | 画面重点 |
|---|---|---|---|---|
| 一键擦除 | 一键擦掉手写，秒变空白卷 | 切「原图 / 擦除后」 | 2 小节 | 对比瞬间 |
| AI 搜题 | 拍一下，AI 分步讲解 | 滚动看解析 | 2 小节 | 公式排版 |

规则：
- **一个镜头只讲一个卖点、只有一个主要动作**；同一种动效（冲击缩放、贴纸弹入）不要每个镜头都用。
- 口播一句 ≤ 15 字（约 3 秒），否则一个镜头放不下，节奏会拖。
- 每个卖点先想「用户为什么在乎」，口播说结果而不是功能名（「秒变空白卷」而不是「支持擦除」）。

## 3. 分镜与能量曲线

广告式结构（58 秒参考，116 BPM，1 小节 ≈ 2.07 秒）：

| 段落 | 时长 | 内容 | 剪法 |
|---|---|---|---|
| 钩子 | 1–2 小节 | 痛点提问（「试卷写满了，还想再练一遍？」） | 0 秒出大字标题，问题画面 |
| 反转 | 2–3 小节 | 核心卖点前后对比 | 唯一一次「闪白」转场 + 惊叹贴纸 |
| 卖点快切 | 每个 1–2 小节 | 其余卖点 | **卡在重拍上硬切** + 切入冲击缩放 + 「嗖」声；录屏 1.4–2× 加速 |
| 高潮 | 2 小节 | 一句情绪话（「辅导作业，从此轻松！」） | 纯背景 + 大字 + 彩带特效 + 点赞贴纸 |
| 行动号召 | ≥ 3 秒 | Logo + 「打开网页 立即体验」+ 网址 | 静止，可停 3–6 秒 |

- **能量曲线**：钩子抓人 → 反转最高点之一 → 卖点段平稳快切 → 高潮 → 结尾收住。
- **全片转场 ≤ 3 个**（反转、换场景、进结尾），其余卡点硬切；审片器超过 `max(5, 每分钟 2 个)` 会报。
- **卡点**：先 `beat_detect.py`；配乐从第一个重拍开始（`source_start = downbeats[0]`），每个镜头的结束取「解说结束 + 0.2 秒」之后的第一个重拍。卡点误差 ≤ 3 帧。
- **停留**：品牌名 / Logo 至少停 1 秒；关键大字出现后停 ≥ 0.5 秒再动。节奏宁可先保守：放慢容易，加快通常要返工。

把分镜写成表（镜头 id、录屏名、起点偏移、倍速、标题、口播、贴纸、转场、音效），共创模式下给用户确认后再录屏。

## 4. 录屏（真实页面）

用 `scripts/web_recorder.py` 的 `record_web_hidpi()`（DevTools 截屏流，按设备像素采集）：

```python
from web_recorder import record_web_hidpi, smooth_scroll
def act(page, ready):
    page.goto(URL); page.get_by_text("拍照处理").wait_for()
    ready()                      # 画面就绪：剪辑从这里开始截取
    page.wait_for_timeout(1500)
    smooth_scroll(page, 400)     # 移动端模拟下 mouse.wheel 不生效
r = record_web_hidpi(URL, "clips/home.mp4", act, viewport=(432, 768), dpr=2.5, storage_state="state.json")
# r = {"path": ..., "ready": 4.7, "end": 12.2}  —— 记进 marks.json
```

- **每个功能录一段**，不要一镜到底；先登录一次存 `storage_state`，其余镜头复用。
- 触控圆点、禁止选中文字已内置；点击前把鼠标移过去停 0.25 秒，看起来像真人操作。
- 录完每段抽 4 帧拼图（就绪后均匀取）用 Read 看：有没有白屏、加载转圈、选中文字、弹窗。
- 产品自身的问题（这次：辅导助手的回答显示 Markdown 原文）先修产品再录，不要硬剪进成片。
- 录屏里会出现的界面文字也要符合宣传口径（这次：首页「所有功能免费」标签 → 让镜头在跳转首页前结束）。

## 5. 装配（剪映草稿）

竖屏「手机卡片」版式（不发短视频平台时，可以不留平台安全区）：

| 元素 | 参数（1080×1920） |
|---|---|
| 背景 | 品牌渐变图铺满全片（主轨），PIL 生成 |
| 录屏 | 画中画轨，`scale≈0.66`，`矩形` 蒙版 `round_corner≈10` + `add_video_shadow` |
| 切入冲击 | 缩放关键帧 1.08× → 1.0×（0.22 秒）→ 1.03×（缓慢推近到镜头结束） |
| 标题 | 顶部，白字 + 品牌深色圆角底（`TextBackground`），入场「弹簧」 |
| 字幕 | 底部，白字深色描边，字号 ≥ 10，入场「向上滑动」 |
| 贴纸 | 只在 2–3 个关键镜头，必须是本机已下载的（`add_sticker` 会告警） |

- 标题和录屏之间留空隙，别压住录屏顶部（用户反馈过「标题和内容重叠」）。
- 解说用 `add_narrated_subtitles`（剪映朗读 SAMI，按标点断句，配音和字幕自动对齐），先算出每个镜头的解说时长，再按重拍定镜头长度、按 `时长 × 倍速` 截录屏。
- 所有挑选的视觉素材（字体、动画、贴纸、特效、转场）先看封面对比图（`docs/agent-playbook.md` 第 7 节），并告诉用户选了什么。

## 6. 声音（画面锁定后再做）

- 配乐：免费曲库按情绪选（广告感：「轻快的宣传音乐」等），音量 0.75，`auto_duck` 让人声。
- 音效：每次切镜一声「嗖」（0.6 秒，切点前 0.12 秒起），贴纸出现「啵」，高潮「叮铃闪亮」。同时出现的音效放不同轨。
- 交付两版更稳：带配乐 / 不带配乐（方便用户换音乐）。

## 7. 审片与交付

1. `layout_preview.py --auto`：版式、字号、对比度、闪帧、转场数量。
2. `jy_preview.py` 在剪映里截关键时刻：文字背景、贴纸、特效、蒙版只能这样核对。
3. **独立复核**：让一个不知道制作过程的子代理只看成片关键帧和分镜表，逐镜头写问题，每条引用时间点 / 帧图。
4. 交付前自己「打开 → 关闭 → 再打开」一次，确认素材库没有「媒体丢失」（`rules/pitfalls.md` A 节）。
5. 告诉用户：草稿名、时长、选了哪些素材（音频要用户自己听）、已知问题；**请用户改完要重剪时先关掉草稿**。

## 隐私

剪映 macOS 草稿的 platform 字段带设备标识；不要直接把草稿目录发给别人，对外只发导出的成片。录屏里的测试账号、网址如果不能外传，导出前换掉。
