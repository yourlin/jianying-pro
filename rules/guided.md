# 引导模式（导演流程）

用户把素材交给你、但没说清（或说不清）要剪成什么样时，不要直接动手剪。按下面 6 步走，**每一步的选择都由用户决定**，你负责分析、给出带理由的默认选项、把选择落实成分镜表。

```
① 读素材 → ② 引导选择 → ③ 选素材 → ④ 写剧本 + 编译分镜（用户确认）→ ⑤ 装配 → ⑥ 审片（用户确认）
                                              ↑__________________________________|
```

## ① 读素材（不问用户）

```bash
python <SKILL_ROOT>/scripts/analyze_footage.py <主视频> [--assets <素材目录>] [--language zh] [--prompt "专有名词"]
```

得到 `analysis.json`：画幅、时长、静音气口、镜头切换、**人脸位置和可放插卡的区域**、语音转写（词级时间戳）、素材目录里的图片 / 视频及方向，以及场景推断。素材多、质量参差时，再跑 `shot_quality.py` 给镜头打分，挑掉模糊、抖动、过曝的废片。用户给了参考视频时，跑 `reference_analyzer.py` 反推场景 / 风格，作为第二轮的推荐项。口播素材在写剧本前先跑 `speech_cleanup.py`（同一句说了多遍时用 `best_take.py`），后面的字幕和定位都用它输出的 `transcript`。详见 `rules/quality.md`。改已有草稿时，再跑一次 `layout_preview.py --draft <草稿名> --auto` 看现状，并 Read 对比图，把问题列出来（作为后面选择的依据）。

## ② 引导选择（用 AskUserQuestion，每轮最多 4 题）

每题把**根据素材推断的选项放第一个并标"(推荐)"**，说明里写一句为什么。用户选了"Other"就按用户的话来。

**第一轮：定方向**

| 问题 | 选项来源 |
|---|---|
| 场景 | `references/scenes/`：口播知识 / Vlog / 教程录屏 / 带货种草 / 影视解说 / 卡点混剪 / 剧情短片 / 宣传片 / MV。推荐 = `analysis.json` 的 `scene_guess` |
| 风格 | `references/styles/`：国风古韵 / 科技 / 清新文艺 / 综艺活泼 / 商务简约。推荐按内容主题（如讲汉字 → 国风） |
| 平台与画幅 | 抖音 / 视频号竖屏 9:16、小红书 3:4、B 站横屏 16:9。推荐 = 素材方向 |
| 成片时长 | 场景文件里的建议时长；素材本身较短时推荐"保留全部内容，只剪气口" |

**第二轮：定细节**（按场景文件的"引导问题"挑最多 4 题，常见的）

- 字幕：中文 / 双语（中 + 英，或外语 + 中文翻译）/ 只有关键词花字 / 不加
- 节奏：剪掉所有气口（紧凑）/ 只剪 0.8 秒以上的停顿（自然）/ 不剪
- 包装强度：克制（只有字幕 + 少量标注）/ 适中（标题、插卡、1～2 处特效）/ 丰富（综艺花字、音效、贴纸）
- 插卡怎么放（人脸占满画面、`card_zones` 为空时必问）：整屏切到图片、人声继续 / 真人缩成小窗、图片放大 / 只在说完一句的间隙短暂压屏

**第三轮：确认素材意图**（素材目录里有图片 / 视频时）

列出每个素材 + 你认为它对应哪句台词，问用户对不对、要不要用。素材方向和画布不一致时要说明只能做插卡。

## ③ 选素材（看图，不凭名字）

按风格文件的白名单和"候选关键词"搜，**每类出一张封面对比图让用户挑**（SKILL.md 第 3 条）：

```bash
python <SKILL_ROOT>/scripts/preview_assets.py "<关键词>" -c panel_text_templates --ready -l 12   # 标题模板
python <SKILL_ROOT>/scripts/preview_assets.py "<关键词>" -c panel_flower_texts -l 12            # 花字
python <SKILL_ROOT>/scripts/preview_assets.py "<关键词>" -c panel_transitions -l 12 --frames 3  # 转场
```

用 Read 看图后，挑 3～4 个最合适的作为选项（选项的 `preview` 写编号和理由），让用户选。配乐用 `asset_search.py "<情绪关键词>" -c cloud_music_library` 找 3 首，说明情绪和时长，请用户在剪映里试听。用户想不出来时，就用风格文件的默认值。需要 B-roll 时用 `broll_fetch.py`（`rules/quality.md`）。

## ④ 写剧本（用户确认后才装配）

开头先按 `prompts/hook_writer.md` 写 3～5 个钩子，让用户选一个。再按 `references/script_schema.md` 写剧本 `script.json`（放在用户项目目录，不放 skill 里）。剧本只写内容：
- 段落：用途，以及用台词定位的时间；
- 每段的元素：标题、点题字、插卡 + 标注、关键词、词卡、CTA、结尾特效、音效；
- 段落开头的运镜。

**剧本里不写坐标、字号、字体、花字。** 这些由三层规范自动决定：
- 场景 `references/scenes/<id>.json`：段落结构、节奏、元素时长、插卡策略、运镜白名单；
- 风格 `references/styles/<id>.json`：各角色的字体、花字、字号，转场、特效、调色、配乐；
- 画幅 `references/formats/<id>.json`：画布、安全区、位置槽、真人小窗、字幕字号。

写剧本时遵守：
- 场景规范 `beats` 里的结构：每段的用途、时长占比、必须有 / 不能有的元素；
- `references/methodology/` 的通用规则：钩子、节奏、字幕断句、插卡、运镜、音频；
- 版面：插卡页 / 结束卡按 `layout.md`，元素只放进画幅规范的区域，不写坐标；
- 镜头语言、调度和剪辑原则（`shot_grammar.md`、`staging.md`、`edit_grammar.md`）：景别、头顶空间、轴线、正反打、动作中切、转场的含义和时长、跳切、J/L cut；
- 想用特效、合成、卡点类效果时，先查 `jianying_recipes.md` 里有没有现成的配方；
- 每段写 `purpose`；插卡要和台词对应；**没有叙事作用的特效不加**。

然后编译成分镜表，再**用表格把分镜给用户看**：镜头 / 时间 / 台词 / 画面（主画面 + 插卡 + 文字）/ 用途。

```bash
python <SKILL_ROOT>/scripts/script_compiler.py script.json -o storyboard.json
```

用户改内容，就改剧本重编译。用户要换画幅或风格（比如再出一版横屏、科技风），加 `--format` / `--style` 重编译即可，剧本不用动。

## ⑤ 装配

```bash
python <SKILL_ROOT>/scripts/storyboard_builder.py <分镜表.json> --preview
# 或者一步到位: 编译 + 装配 + 截图
python <SKILL_ROOT>/scripts/script_compiler.py script.json -o storyboard.json --build --preview
```

装配器按分镜表生成草稿，然后自动跑审片器；`--preview` 会在剪映里截取每个镜头（macOS，剪映停在首页）。装配报告里的警告（素材找不到、插卡太短、文字被剪点截断）要处理掉。

有 BGM 和人声时用 `auto_duck()` 做 ducking；包装强度不是"克制"时，用 `sfx_designer.py` 铺音效；多段素材色调不一致时，用 `match_color()` 统一调色；卡点场景用 `beat_snap.py`（见 `rules/quality.md`）。

## ⑥ 审片（用户确认后才算完成）

1. Read 审片器的 `sheet.jpg` 和报告，`[字号]` `[安全区]` `[平台UI]` `[重叠]` `[蒙版]` `[对比度]` `[字体]` `[闪帧]` 必须清零，回到 ④ 改分镜重跑。
2. Read 剪映截图（必做，审片器通过不代表画面正确），看花字 / 模板的真实效果、插卡和人脸的关系、文字清不清楚。
3. 把截图和"改了什么、为什么"给用户看；提醒用户在剪映里听一遍音量平衡（BGM 和人声）。
4. 用户提意见 → 改剧本（内容）或改规范（呈现方式，对所有项目生效）→ 重新编译、装配。
5. 版式问题清零后跑 `quality_review.py`，Read `viewer_sheet.png`，从观众角度看钩子、节奏和死区；交付时用 `cover_maker.py` 出封面，用户要多版本时用 `variants.py`。
6. 写剧本前，可以按 `methodology/edit_grammar.md` 末尾的「剪辑师常见错误」自查一遍。
7. 剪映截图里发现的通用问题（比如某种花字在亮背景上看不清），要写回风格 / 画幅规范，不要只在这个项目里改。

## 原则

- **选择题优先**：能给选项就不要让用户写作文；每题的推荐项都要有依据（素材分析结果 / 场景规范 / 风格规范）。
- **一次只问必要的**：已经能从素材或用户的话里确定的，不要再问；用户说"你决定"时用推荐项。
- **规范是硬约束**：风格文件里的数值和白名单不能随手改；用户要的效果超出规范时，先说明会有什么问题，用户坚持就照做，并在分镜的 `note` 里记下来。
- **不确定就看图**：素材效果、插卡位置、文字压不压脸，都以对比图 / 剪映截图为准。
